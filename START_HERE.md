# Avelora Combat Manager — Fixed Online Setup

**This is the corrected online version.** The previous ZIP contained a typo: the server checked `AVELORA_DM_PASSWORD` but its error message said `AVALORA_DM_PASSWORD`; Docker also misspelled the online and data settings. All three names are consistent in this version.

## First: protect your previous work

- **Do not delete your existing Railway volume** or your existing project. The `/data` volume can contain saved Pokémon and campaign progress.
- A password was visible in a previous screenshot. **Never reuse that password.** Choose a fresh, unique password of at least 16 characters, preferably generated by a password manager. Do not share it in chat, screenshots, or GitHub.
- If you already have an Avelora GitHub repository and Railway service, **update that repository** instead of starting a new Railway project. The old Railway service can redeploy the corrected code and keep its attached `/data` volume.

## A. Update your existing app (recommended)

1. Unzip this download on your Mac. You should see `Dockerfile`, `server.py`, `rules.py`, `offline_data.json`, `static/`, `tests/`, and this guide.
2. Open your existing Avelora GitHub repository. Replace its `Dockerfile` and `server.py` with the corrected files in this download (the remaining app files are unchanged). You can use **Add file → Upload files** and commit the replacements. Make sure they are at the **repository root**, not inside another folder.
3. Open Railway → your **Avelora service** → **Variables**. Add or update exactly **`AVELORA_DM_PASSWORD`** (note **AVE**, not **AVA**) with your **new** password of at least 16 characters. The old misspelled `AVALORA_DM_PASSWORD` variable is not used by this code; remove it after you have confirmed the correct one is set. Never paste your password into GitHub.
4. The updated `Dockerfile` already supplies `AVELORA_ONLINE=1`, `AVELORA_DATA_DIR=/data`, and `PORT=8080`. If Railway Variables also contain `AVELORA_ONLINE=1` and `AVELORA_DATA_DIR=/data`, you can leave them. If Railway has a `PORT` variable, use that port for the domain; otherwise use **8080**.
5. Verify the **Railway volume remains attached to the same service at `/data`**, and that the service uses **one replica**.
6. Commit the GitHub changes. Railway should deploy automatically; if not, choose **Deploy** for the latest commit. Wait for the newest deployment to say **Active** and check **Deploy Logs** for `Avelora online server listening on port ...`.
7. Open your Railway HTTPS website. If you need to generate a domain, use **Settings → Networking → Generate Domain** and select port **8080** (or the value of your `PORT` variable).
8. Open `https://YOUR-APP.up.railway.app/api/session` in a private/incognito browser window. You should see `"online": true` and `"host_login": true`. Go back to the homepage, select **Dungeon Master**, and enter your new password.

**Do not upload the ZIP file itself to GitHub.** GitHub needs the unzipped source files, with `Dockerfile` and `server.py` at the root and the three browser files inside `static/`.

## B. Fresh deployment (only if you truly want a new project)

1. Keep your existing project and `/data` volume untouched as a backup until the new one is verified.
2. Create a **private** GitHub repository, and upload the **unzipped contents** of this folder (not the ZIP), preserving `static/` and `tests/` directories.
3. In Railway, choose **New Project → Deploy from GitHub Repo** and select your repository.
4. Set one secret variable: `AVELORA_DM_PASSWORD` = a **new** password at least 16 characters long. Online mode, data path and port are already set by the Dockerfile.
5. Attach a **persistent Railway Volume** to that service at mount path `/data`. Do this **before** using the app for a real campaign. Keep **one replica**.
6. Wait for the deployment to become Active. In **Settings → Networking**, generate a Railway domain using **port 8080** unless `PORT` is set differently.
7. Check `/api/session` for `"online": true` and `"host_login": true`. Sign in on the homepage using your DM password.

**Important:** A new Railway volume starts with a new campaign. Data on the old volume does not automatically move to the new service. If you have existing campaign data, updating your current service (Section A) is safer.

## What the DM and players do

- DM: log in with the private DM password, manage Pokémon, approve players, control battles, award EXP and override outcomes.
- DM: open **Overview → Copy player invite link** and share it with up to ten players. Never share your DM password.
- Players: follow the link, enter a Trainer nickname, and wait for DM approval. They see only their Pokémon and limited opponent information.
- Players can enter physical dice results, choose battle moves, and request new moves or full party/storage changes; the DM approves or denies team/move changes.
- Saves go to SQLite under `/data`. After each session, use **DM Tools → Export full campaign JSON** to keep an additional backup on your Mac.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `Missing or too-short AVELORA_DM_PASSWORD` | In the correct Railway **service/environment**, set `AVELORA_DM_PASSWORD` to a **new** 16+ character password; apply pending changes. Do not use `AVALORA_DM_PASSWORD`. |
| `"online": false` at `/api/session` | Verify the corrected **Dockerfile** was committed and deployed, and `AVELORA_ONLINE=1` isn't overridden by a different variable. |
| Domain asks for a port | Use **8080**, unless Railway has a different `PORT` variable; the server listens on that port. **8765 is local Mac mode only.** |
| Website cannot load | Check **Deploy Logs**, active deployment status, and domain target port. |
| Campaign seems reset | Verify the original `/data` volume is still attached to the same service/environment. Do not delete the volume. |
| No DM login | Check `/api/session` and confirm `"host_login": true` and `"online": true`. |

## Testing on your Mac (optional)

From this directory in Terminal:

```bash
python3 -m unittest discover -s tests -v
```

The tests start a local server in simulated online mode, test DM login, player approvals, and battle/security flows. They **cannot guarantee Railway deployment** until you deploy and verify the real website.

## Ten-player update

- The campaign now supports **up to 10 approved Trainers**, each with their own login session and DM-approved move/team changes.
- Up to **20 pending join requests** may wait for DM approval. Once 10 Trainers are approved, new joins are rejected until an approved Trainer is removed.
- The six-Pokémon party limit is **per Trainer**, not a campaign-wide limit. Battle size remains **20 vs. 20**.
- **Existing saved campaigns remain compatible.** No database reset or new Railway volume is required.
- To upgrade an existing GitHub/Railway installation, replace `server.py` at the repository root and `static/app.js` inside the `static` folder. Commit both, then verify Railway deploys the new commit. Do **not** delete or detach `/data`.
